# Запуск Angular приложения в Docker с Hot Reload

Этот проект поддерживает запуск Angular приложения в Docker с автоматической пересборкой при изменении кода.

## Быстрый старт

### 1. Запуск в режиме разработки (с hot reload)

```bash
# Используя готовый скрипт
./scripts/dev-docker.sh

# Или вручную
docker compose -f docker-compose.dev.yml up --build
```

### 2. Запуск в продакшн режиме

```bash
docker compose up --build
```

## Что происходит в режиме разработки

1. **Dockerfile.dev** - специальный Dockerfile для разработки, который:
   - Устанавливает Angular CLI и зависимости
   - Запускает `ng serve` с параметрами для Docker
   - Использует polling для обнаружения изменений файлов

2. **docker-compose.dev.yml** - конфигурация для разработки:
   - Монтирует исходный код в контейнер через volumes
   - Исключает `node_modules` для избежания конфликтов
   - Настраивает порт 4200 для Angular dev server

3. **Hot Reload** работает благодаря:
   - Монтированию папки `src` в контейнер
   - Использованию `--poll 2000` для проверки изменений каждые 2 секунды
   - `--host 0.0.0.0` для доступа извне контейнера

## Доступ к приложению

После запуска приложение будет доступно по адресу:
- **Режим разработки**: http://localhost:4200
- **Продакшн режим**: http://localhost:4200 (через nginx)

## Изменение кода

При изменении любого файла в папке `src/`:
1. Angular dev server автоматически обнаружит изменения
2. Произойдет пересборка приложения
3. Браузер автоматически обновится (если открыт)

## Остановка

```bash
# Остановить контейнеры
docker compose -f docker-compose.dev.yml down

# Или остановить все контейнеры
docker compose down
```

## Troubleshooting

### Проблема: Изменения не отражаются
- Убедитесь, что файлы изменяются в папке `src/`
- Проверьте, что volumes правильно смонтированы
- Попробуйте перезапустить контейнер

### Проблема: Порт занят
- Измените порт в `docker-compose.dev.yml` (например, 4201:4200)
- Или остановите локальный Angular dev server

### Проблема: Медленная сборка
- Это нормально для первого запуска
- Последующие сборки будут быстрее благодаря кэшированию

## Переменные окружения

Все переменные окружения из `docker-compose.yml` перенесены в `docker-compose.dev.yml`. При необходимости их можно изменить в файле конфигурации.
